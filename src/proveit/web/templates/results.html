Most slop does not invent code. Existence checks alone caught 2 of 31 dev slop reports. The rest cite real functions and make false claims about them, which is why the judgment stage reads the real code.

Reporters read releases, not master. All five v1 false alarms were real 2026 reports about code that master had already changed by the time they were filed. Showing the release version of each changed function, with the commits in between, removed them.

The judge can be fooled; receipts catch it. On one slop report, Ultra "confirmed" a quote of nghttp2's documentation that the report invented. The quote was not in the fetched page, so the verdict was withdrawn.

Limitations

Two real CVE reports in the test split were wrongly deprioritized: CVE-2023-38546 (the judge read cookie loading from a file named "none" as intended behavior) and CVE-2022-27776 (it misread a redirect condition).

The evaluation uses one project. curl is a demanding case (C, 40,000 commits, a strict security policy), but other projects will need their own source paths and policy file.

Most real reports end at "needs a human": ProveIt is built to be safe, not decisive, when the evidence is mixed.

Reproduction of proof-of-concept code in a sandbox is not implemented yet; verdicts come from reading code.
